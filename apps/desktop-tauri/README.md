# H-Gripe Desktop (Tauri shell)

Phase 2 desktop shell for H-Gripe. It wraps the `hgripe-api` crate in a
[Tauri](https://tauri.app) window and exposes the API-first workflow.

## Positioning: the node editor is the app

The desktop app is a **single React front end** ([`studio-ui/`](studio-ui/))
that boots directly into H-Gripe's in-house node editor — the main canvas.
(Earlier builds embedded ComfyUI as an "Advanced Canvas" escape hatch; that has
been removed. The legacy control-console shell — Dashboard / PSD Studio /
Run Task / History / PSD as top-level tabs wrapping the editor — has also been
removed: everything is carried by canvas cards/nodes, the editor toolbar, and
the bottom production drawer.)

```
H-Gripe Desktop (single React app)
  └─ Node Editor  H-Gripe's own visual workflow canvas (React Flow)
       ├─ Toolbar        run / batch / history / project / snapshots / language
       ├─ Cards & nodes  generate, PSD chain, media cards, review gates, …
       └─ Production drawer  Edit/Timeline + Grade, on-demand editors & export
```

The whole front end is a single Vite + React + TypeScript app in
[`studio-ui/`](studio-ui/) that builds to the Tauri `frontendDist` at `dist/`
(gitignored); the Rust backend lives in `src-tauri/`. The editor lives under
[`studio-ui/src/editor/`](studio-ui/src/editor/) with one i18n system
([`src/i18n.ts`](studio-ui/src/i18n.ts)) and one CSS design system
([`src/styles.css`](studio-ui/src/styles.css)). IPC goes through typed
wrappers under [`studio-ui/src/bridge/`](studio-ui/src/bridge/) whose command
argument / return types mirror the Rust `#[tauri::command]` signatures, so a
rename or shape change surfaces as a `tsc` error instead of a silent runtime
drift.

There is no H-Gripe account/login surface in the desktop app. Third-party API
keys and provider profiles remain local API configuration files handled by
`hgripe-api-config` and consumed by generate nodes when a profile is selected.

> **`dist/` is a build artifact.** It is generated by `studio-ui` and
> gitignored. The Tauri before* hooks build it for you; a bare `cargo run` does
> **not** run these hooks. In dev builds the window points at
> `http://localhost:5173`, so it will show `localhost refused to connect` unless
> Vite is already running. Use `scripts\dev-desktop.cmd` for the one-command
> path.

> **Security (CSP):** `tauri.conf.json` sets an explicit `app.security.csp`
> instead of `null`. It keeps `default-src 'self'` while allowing what the app
> actually needs: `style-src 'unsafe-inline'` (React / React Flow inject
> styles), `img-src data: blob:` (thumbnails are read back as data URLs), and
> `connect-src ipc: http://ipc.localhost` (Tauri IPC). The bundle is loaded as
> an external module script (`script-src 'self'`, no inline scripts). If a
> future feature needs a remote origin (web fonts, a hosted asset), widen the
> matching directive rather than reverting to `null`.

## Prerequisites (Windows)

- Rust toolchain `stable-x86_64-pc-windows-msvc`.
- Visual Studio Build Tools 2022 with the C++ workload + Windows SDK.
- WebView2 runtime (preinstalled on current Windows; otherwise install the
  Evergreen runtime).

## Build & run

```sh
# One-command local desktop dev from the repository root.
# Starts Vite on localhost:5173, waits for it, then runs the Tauri shell.
scripts\dev-desktop.cmd

# Build the front end for artifact-based runs. A plain `cargo run` does NOT
# build it or start Vite. The Tauri CLI runs before* hooks automatically.
npm --prefix apps/desktop-tauri/studio-ui ci
npm --prefix apps/desktop-tauri/studio-ui run build   # -> apps/desktop-tauri/dist

# from the repository root (only after the front end is built)
cargo run -p hgripe-desktop          # debug run
cargo build -p hgripe-desktop --release

# or, with the Tauri CLI (npm i -g @tauri-apps/cli) — builds the front end
# for you (before* hooks)
cd apps/desktop-tauri
tauri dev                            # debug, with the frontend build hooks
tauri build
```

For front-end development you can also run the Vite dev server
(`npm --prefix apps/desktop-tauri/studio-ui run dev`) or type-check in isolation
(`npm --prefix apps/desktop-tauri/studio-ui run typecheck`).

If `cargo run -p hgripe-desktop` opens a WebView page saying
`localhost refused to connect`, the Rust shell is running but Vite is not
listening on port 5173. Use `scripts\dev-desktop.cmd`, or start the frontend
manually first:

```sh
npm --prefix apps/desktop-tauri/studio-ui run dev
cargo run -p hgripe-desktop
```

App icons are generated from `app-icon.png` via `tauri icon app-icon.png
--output src-tauri/icons`.
